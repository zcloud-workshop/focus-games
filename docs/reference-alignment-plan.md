## 4. 共同实现调整

### 4.1 设置与运行流程

- 目录支持每个训练自己的模式、预设及自定义字段, 取消统一假设“所有训练恰好三个无条件可选难度”.
- 记录参数的单位、范围和组合约束. 非法输入在设置处直接说明, 不启动不可能完成的训练.
- 设置放在训练弹窗内, 首页继续只显示必要信息.
- 解锁按训练、模式和难度保存, 门槛来自参考实测, 不能用累计完成次数统一替代.
- 保留 `mountGame` 的开始、结束和清理契约. 30 项实现按训练拆到 `src/games/` 等小文件, 由现有入口分派, 不引入额外框架或通用游戏编辑器.
- 复用随机排列、N-Back 比较、计时、左右响应、结果和清理等已有能力; 只提取确实被多项训练共用的逻辑.
- 动态视觉任务按实际时间驱动呈现, 退出时停止动画. 声音任务在用户开始操作后启用音频, 退出时停止声音及调度.
- 重复点击、长按重复键、最后一题连点、超时边界和退出后的回调都要有明确归属, 一轮最多提交一次结果.

### 4.2 成绩与历史兼容

当前结果只有 `value`、`detail` 和 `duration`, 当前个人最佳只按 `game + level` 比较. 新模式、自定义参数和规则修正后, 这一分组不足以保证成绩可比较.

最小调整方向:

1. 在现有记录上补充模式、设置快照、规则版本及必要的分项指标. 主成绩继续提供数值和单位, 供现有记录页使用.
2. 个人最佳按游戏、模式、相同设置和规则版本分组, 明确高分更优或低分更优. Go/No-Go、Dual N-Back、各反应时效应等保留分项结果.
3. 比较前排除不合格的反应时样本, 无有效样本时显示无结果, 不保存 `NaN`、无穷或伪造的 0ms 效应.
4. 兼容读取 `focus-lab-v1`, 保留用户已有记录、收藏和主题. 旧规则成绩单独标识, 不与新规则争夺个人最佳.
5. 特别处理现有 `numbers`: 它的旧成绩来自整串数字输入, 既不是新的空间数字记忆, 也不等同于逐个呈现的数字广度. 不自动改名迁移成任何一个新项目的有效成绩.
6. 原有 12 个游戏 ID 尽量保持稳定. 新增数字广度使用独立 ID, 收藏与旧链接不因改目录而丢失.
7. 更新所有受影响调用点: `bestRecord`、`readSaved`、`bestText`、`showResult`、导出、统计、解锁判定和现有测试. 未完整完成的训练不能触发新纪录或解锁.

### 4.3 目录与辅助能力

- 分类调整为 7/6/10/3/4 的五组, 搜索和收藏覆盖全部 30 项.
- 每日挑战继续使用实际可运行、可保存的训练, 不把未完成的新游戏加入挑战.
- 成绩列表、导出和本地排行榜口径同步支持模式及自定义设置, 保持当前本机保存方式.
- 训练规则用短说明表达, 长篇参考资料保留在开发文档中.

## 5. 实施顺序

### P0. 固定逐项规则基线

- [ ] 为 30 项逐项完成低/中/高预设、附加模式和自定义面板的操作核验.
- [ ] 记录参数默认值、范围、步长、单位及解锁条件, 附参考地址和检查日期.
- [ ] 每项至少观察一次开始、正确、错误/超时、结束和重开的流程.
- [ ] 记录主成绩、分项指标、最佳方向和排行榜分组规则.
- [ ] 对延迟、目标比例、误差公式、随机分布等初始页面看不出的内容明确标记待证; 未取证的关键规则不进入“已对齐”状态.

交付: 一份可逐项执行的规则对照表. 此阶段完成后, 再按已确认参数写代码, 不继续根据名称猜玩法.

### P1. 公共设置与成绩兼容
