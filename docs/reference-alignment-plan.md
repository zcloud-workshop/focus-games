## 1. 目标、范围与原则

### 1.1 目标

对齐三个来源的训练规则、模式、实际提供的难度与可调参数、解锁条件、操作反馈和成绩口径. 同名训练玩法不同时, 增加独立模式和成绩分组, 不以完成其中一个版本代替其他来源.

### 1.2 范围外

- C27 SBTI 娱乐人格问卷, 以及评估栏目中的 ADHD 筛查、综合认知问卷和营销性疗效描述.
- 用户画像、全国百分位、星级和年龄/性别常模. 本站没有统计依据, 不编造, 也不把游戏成绩解释为诊断.
- 后端、登录和跨设备同步. 参考站的排行榜规则只用来确定本机排行的分组.

### 1.3 产品与原创约束

- Apple 风格的简约布局, 黑白灰界面和少量蓝色强调, 明亮/深色主题, 简短中文文案.
- 训练刺激的颜色按玩法呈现, 主题样式不改变颜色判断、Go/No-Go 等任务的含义.
- 保留收藏、每日挑战、本地记录、导出和手机适配.
- 参考来源和差异只记录在开发文档中, 产品页面保持简约.
- 继续使用 Vite、原生 JavaScript 和 Cloudflare Static Assets, 不引入框架或服务端.
- 对齐的是玩法和规则, 不复刻具体游戏. 名称、角色、美术、音乐、关卡和外观使用本站原创设计, 参考站的主题、插画、音频、品牌和长篇文案不搬用; 关卡与题目由本站生成或编写.
- 来自具体游戏、品牌或商业测验的名称 (2048、F1、双重决策、威斯康星、瑞文) 前台改用描述性名称. 对应 ID 改为 `number-merge`、`card-sorting`、`matrix-reasoning`、`field-of-view`, 起步灯作为 `reaction` 的一个模式.

## 3. 共同架构

### 3.1 目录与规则配置

- 目录只保留列表、搜索和收藏需要的轻量元数据: ID、名称、分类、简述、来源入口和上线状态. 模式、预设、可调字段、解锁、计分与资格规则放在各训练模块中, 打开训练时加载.
- 每个模式配置: 来源入口; 预设; 实际存在的可调字段及其单位、默认值、范围、步长和组合约束; 解锁规则; 主成绩的单位、方向和合法值域; 分项指标; 结束原因; 计分资格; 输入方式; 页面隐藏策略. 不再假设每项恰好三档难度或都有自定义.
- 同一主体的不同来源规则是独立模式, 成绩分组隔离. 轮数、计时和结束策略按模式配置, 不用统一策略覆盖 (如数字广度同长度重试、连线分段休息、PVT 持续等待、起步灯连续有效样本). 参数组合只开放已确认的有效组合, 非法输入在设置处说明, 不启动不可能完成的训练.
- 设置放在训练弹窗内, 首页只显示必要信息. 解锁按训练、模式和预设保存, 门槛来自取证, 没有门槛的模式不加锁.
- 分类在 P1 定稿: 保留来源 A 的 7/6/10/3/4 映射, 为来源 B/C 的推演、感知、算数、分散注意、持续警觉等内容补充分类, 标签保持简短, 工具单独分组. 来源 C 的按能力浏览只作参考, 同一训练只出现在一个分类.

### 3.3 输入、时序与生命周期

- 计时响应统一在 `pointerdown` 或 `keydown` 时记录. 现有 `action` 监听 `click` (基线 `src/games.js` 第 22 行), 松开时才触发, 反应时包含按压时长. 取证时记录参考站的触发时机, 若参考站在松开时计时, 登记为已知差异. 同一次操作产生的触摸与鼠标兼容事件只计一次; 键盘自动重复单独标记, 由各训练决定是否计入.
- 刺激在 `requestAnimationFrame` 中切换并记录实际呈现时刻, 反应时从该时刻算起. 现有反应速度在绘制前取时间 (基线第 224 行). 短暂呈现的实际时长按显示帧记录, 不把设定值当作实测值.
- 运动本身是刺激的训练由 JS 按时间驱动, 不依赖 CSS 过渡. 现有减少动态效果规则 (`src/style.css` 第 410 行) 会关闭全部 CSS 动画和过渡: 装饰动画继续遵守; 需要动态画面的训练在开始前说明, 不静默失效.
- 页面隐藏策略按模式配置: 作废 (默认, 即现行为)、暂停, 或继续按实际时间计时 (番茄钟). `src/main.js` 的全局 `visibilitychange` 中断改为读取该配置.
- 右键、空格、触屏、拖拽、滑动、WASD 和长按预览按训练分别绑定. 右键与空格计数不受通用去重或触屏替代影响; 缺少所需设备时明确说明, 不记为等价成绩.
- 重复点击、最后一题连点、超时边界和退出后的回调都有明确归属, 一轮最多提交一次结果. 结束、退出或隐藏时释放定时器、动画、声音和传感器监听.
- 音频和动作感应只在用户操作后启用, 不可用或被拒绝时给出说明并允许继续, 如竹知了退回手势操作.
- 快速闪烁的任务 (RSVP、短暂呈现加遮罩、动态视力) 避免大面积高频闪烁, 开始前提示.

### 3.4 成绩、存储与兼容

基线情况: 记录只有 `game`、`level`、`value`、`duration` 和 `at`; 个人最佳按 `game + level` 从最近 500 条记录中查找; `readSaved` 丢弃 `level` 不在 0-2、`value` 为负或游戏 ID 不在目录中的记录, 而 `persist` 会把过滤后的结果写回 `focus-lab-v1`. 若把新格式记录写入同一个键, 任何仍运行旧版本的标签页 (包括通过 `storage` 事件同步时) 都会永久删除这些记录.

1. 新数据写入 `focus-lab-v2`. 首次读取时从 `focus-lab-v1` 迁移记录和收藏, v1 保持原样, 旧版本标签页和回滚仍可用. 迁移后 v1 若出现新记录 (旧标签页写入), 下次读取时去重合并. 主题键 `focus-lab-theme` 不变.
2. 每次写入前重新读取并合并, 不用内存中的旧副本覆盖. 现有逻辑在训练进行中忽略其他标签页的 `storage` 更新, 结束时会覆盖对方写入的记录和收藏. 读取时保留无法识别的记录和字段, 只在展示时跳过, 写回时原样保留.
3. 记录补充模式、规则配置、设置快照、规则版本、输入方式、结束原因、计分资格和分项指标. 主成绩继续提供数值和单位, 合法值域按模式校验, 允许取证确认的负分.
4. 个人最佳和解锁状态单独保存, 保存成绩时增量更新, 不再从最近 500 条推算, 避免记录滚动后丢失最佳或重新上锁. 最佳按游戏、模式、规则配置、相同设置、输入方式和规则版本分组, 方向由模式定义.
5. 只有有效结算才写入正式成绩. 教程、例题、练习、非计分模式 (如来源 B 的秒针练习)、中断和无效试次标记为不计分, 不触发新纪录或解锁. 按最后成功时刻或到时结算的成绩分别标明; 原始时间、错误罚时和调整后成绩分开保存; 排名资格与本地有效记录分开.
6. 反应时统计前排除不合格样本. 没有有效样本时显示无结果, 不保存 `NaN`、无穷或伪造的 0ms 效应.
7. 逐试次原始数据 (PVT 随时间变化、Flanker 分组等) 设存储预算: 汇总指标长期保留, 原始试次只保留每个模式最近若干次; 写入超出配额时先丢弃最旧的原始试次.
8. 旧记录标为旧规则并保留原难度标签, 单独显示, 不与新规则争夺最佳. P1 迁移后尚未校正的训练继续按原规则记录 (规则版本 1). `numbers` 的整串数字旧成绩不迁移为空间数字记忆或数字广度成绩.
9. 原有 12 个 ID 保持稳定, 收藏和旧链接不丢失; 数字广度使用独立 ID.
10. 工具记录 (番茄钟的完成时段与分钟、竹知了的手动圈数) 单独存放, 不进入正确率、反应时、个人最佳和每日挑战. 今日次数、累计时长和连续天数默认不计工具, 避免一个 25 分钟番茄钟主导统计. 自动演示和跳过的时段不增加完成量.
11. 导出包含数据版本、记录、最佳、解锁和工具记录.
12. 受影响的调用点: `readSaved`、`persist`、`bestRecord`、`bestText`、`showResult`、`recordsContent` (按 `game.levels[record.level]` 显示难度)、`summarize`、导出、`storage` 事件同步、每日挑战和现有测试.

### 3.5 素材、许可与安全策略

- P0 建立素材清单, 逐项记录用途、来源 (自绘 SVG、程序合成或授权素材)、许可与署名和体积. 主要涉及: 图片回溯图片 (T03)、字母语音 (C02)、麻将牌面与声音 (C13)、音色 (A28)、物品图片与词表 (C15)、动物图片 (C22)、默认拼图图片 (T10)、起步灯图形 (C07)、秒针与提示音 (T23、C21) 和竹知了音效 (C30).
- 竹知了页面注明基于第三方开源项目. 复用其代码或资源前核验许可和署名, 否则独立实现运动与音效.
- 现有 CSP 为 `img-src 'self' data:`, 不含 `blob:`. 自定义拼图图片优先用 `createImageBitmap` 解码后绘制到 canvas, 不需要改 CSP; 确需对象 URL 时再评估加入 `blob:`. 音频从本站获取后用 Web Audio 解码, 符合现有 CSP. `Permissions-Policy` 未限制动作传感器.
- 素材放在 `public/` 或随模块打包, 不依赖第三方运行时 CDN.
- 体积预算: 当前入口脚本约 13 KB (gzip). 训练模块和素材按需加载, 入口脚本建议不超过 25 KB (gzip), 超出时说明原因.

### 4.1 批次流程

P1 试点和批次 1-10 都按同一流程推进:

1. 取证: 为本批每个主体建立 `docs/rules/<id>.md`, 覆盖它的全部映射入口. 每个入口至少实际运行一次开始、有效操作、适用的错误或超时、结束和重开流程.
2. 实现: 按已确认的规则写模式配置、纯规则和界面, 不根据名称猜玩法.
3. 测试: 纯规则用固定种子测试, 另测计分边界和成绩分组.
4. 浏览器验收: 第 6.1 节清单和本批重点验收.
5. 预览: 推送批次分支, 由非生产分支构建生成版本预览, 在预览地址验收第 6.2 节.
6. 上线: 合并到 `main` 后自动部署. 按项目约定每个文件单独提交, 合并时保留逐文件提交, 不使用 squash. 生产环境冒烟检查后, 更新本文状态列、README 和首页描述.

取证文件记录: 来源入口与地址、检查日期与方式 (实时运行或页面正文); 模式与预设; 可调字段的默认值、范围、步长、单位与组合约束; 呈现、间隔、响应窗与超时; 输入方式; 错误、超时、漏答、提前与重复输入的处理; 结束条件与结束原因; 主成绩、分项指标、方向与显示精度; 解锁与重置; 计分资格; 排行分组; 待证项与本站决定. 初始页面看不出的延迟、目标比例、误差公式和随机分布明确标为待证, 已运行观察和文字推断分开标注.

取证受阻: 需要登录、依赖服务端或页面不可用而无法运行确认的规则, 记录尝试过程、采用的本站行为和理由, 经用户确认后作为已知差异验收, 不把猜测值标为已对齐.

基线变更: 冻结后参考站新增、下线或修改规则时, 登记到第 7 节并安排到后续批次, 不在进行中的批次静默扩大范围.

并行: P1 完成后, 批次之间只通过公共引擎耦合, 可以并行推进; 同一引擎文件同一时间只由一个批次修改.
